# NuclearLang for Zed

The NuclearLang extension for Zed: a tree-sitter grammar (`grammar/`), the Chernobyl theme and icons, and the language server `nuclear-lsp` (installed by the `nuclear` repository's installer).

```sh
./build.sh                # grammar + extension (wasm32-wasip2) → ~/.local/share/zed/extensions/installed/nuclearlang
```

`./install.sh` builds and installs it if Zed is installed (it needs `rustup target add wasm32-wasip2`; the grammar
is regenerated with `tree-sitter`, `cargo install tree-sitter-cli`, only if `grammar.js` changes). Zed reloads it
by itself. The server is `~/.local/bin/nuclear-lsp` (installed by `./install.sh` with the dialects).

- `zed/grammar/`: a tree-sitter grammar of tokens (comments, strings with `${}`, numbers, decorators, words,
  operators and nested brackets). It never fails on half-written code; the meaning of each name comes from the
  server's semantic tokens. Zed reads grammars from a commit: `build.sh` commits in `zed/grammar/`'s own git and
  writes its `rev` in `extension.toml`.
- `zed/languages/nuclear/`: `config.toml` (the same indentation rules as VS Code; Enter in a `//` continues with
  ` * `), `highlights.scm`, `brackets.scm`, `overrides.scm`, `semantic_token_rules.json` (kinds, library
  functions, deprecated struck through), `tasks.json` (Dragonfly) and `runnables.scm` (▷ on `main()` and on each
  test).
- `zed/src/lib.rs`: starts the server and passes it `lsp.nuclear-lsp.settings`.
- `zed/themes/chernobyl.json` is generated by `theme/build.mjs`; `zed/icon_themes/` and `zed/icons/` are
  generated by `zed/scripts/icons.mjs` from the VS Code icon themes.

Settings, tasks and what Zed does not allow: `spec/flutter.md` §11.3.
