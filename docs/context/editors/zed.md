# Zed extension (`nuclear-zed`, `spec/flutter.md` §11.3)

- `grammar/`: tree-sitter grammar of TOKENS, own git (Zed reads grammars from a commit; `build.sh` commits it and
  writes the `rev` into `extension.toml`).
- `languages/nuclear/`: `config.toml` (VS Code's indentation rules, `documentation_comment` for ` * `),
  `highlights.scm` (in Zed the later pattern wins), `brackets.scm`, `overrides.scm`, `semantic_token_rules.json`
  (`kind`, `defaultLibrary`, `deprecated`), `tasks.json` (Dragonfly run/build/watch/test/repair, device,
  terminal device), `runnables.scm` (▷ on `main(` → `dragonfly-main`; on `@test/@widget/@states("name")` →
  `dragonfly-test` with `$ZED_CUSTOM_test_name`).
- `src/lib.rs`: wasm32-wasip2, `zed_extension_api` 0.7; `nuclear-lsp` from `lsp.nuclear-lsp.binary.path`, the
  PATH or `~/.local/bin` (installed by `install.sh`; finds dialects and defs in `share/nuclearlang`); `settings` →
  `{ nuclear: ... }`.
- `themes/chernobyl.json` GENERATED by `theme/build.mjs`; `icon_themes/` + `icons/` GENERATED by
  `zed/scripts/icons.mjs` from `vscode/icon-themes`.
- `zed/build.sh` builds and installs into `~/.local/share/zed/extensions/installed/nuclearlang` (Zed reloads it);
  `install.sh` runs it when Zed exists (`--no-zed`).
- The server answers `nuclear.showCodeMetricsCodeLensInfo` with `window/showMessage` only for clients whose
  `clientInfo.name` starts with `Zed`.
- Zed does not allow: the device, `.nuc` debugging, build on save.
